V. Detailed Backend Architecture & System Design
The architecture is built on the Backend-for-Frontend (BFF) pattern, using a central server to manage all the complex data sourcing and filtering before delivering it in a fast, clean format to the Next.js frontend (PWA).
A. Core Architecture Stack
| Layer | Technology Focus | Purpose in Welcome SA |
|---|---|---|
| Frontend (F.1) | Next.js (React) | PWA, SSR, and SSG for Fast Loading Speed. Renders the UI and handles user interaction. |
| Backend (B.1) | Node.js Server (acting as BFF) | Serves as the single API layer between the frontend and all external/internal data sources. Crucial for custom filtering (Province, Positive News). |
| Data Storage (B.2) | PostgreSQL (Database) | Stores proprietary data (e.g., manually curated Culture/Tourism guides, User comments, User data). |
| CMS (B.3) | Headless CMS (e.g., Strapi, Contentful) | Manages the structured data for Culture/Explore SA and provides a moderation interface for comments. |
B. Data Flow & Integration (The "Filter" Layer)
The most complex requirement is the Positive News Filter and Localization. This is handled by the Backend (BFF) layer, which acts as a central data hub:
 * Ingestion: The BFF connects to external APIs (News Partners, Project Data Feeds).
 * Normalization: All incoming data is transformed into a standardized format before storage/caching.
 * Custom Logic: This is where the core filtering happens:
   * Localization: When a user requests news for "Gauteng," the BFF only queries the News API or filters the cached data for that province's content.
   * Positive/Development Filter: The BFF runs a lightweight analysis (simple keyword matching against a predefined list of "positive" terms like 'launch,' 'fund,' 'complete,' 'grow') on incoming headlines and summaries to tag content. The frontend then requests content tagged as 'positive.'
 * Delivery: The BFF sends a single, clean JSON payload to the Next.js frontend for maximum rendering speed.
